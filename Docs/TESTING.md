# Testing

Run the default suite with `swift test`. Do not hard-code a test count in
documentation: Swift Testing parameterization expands cases (including 375
fidelity fixtures), and the count changes as regressions are added.

Compile the library against the minimum iOS deployment target separately from
the macOS test host:

```sh
SDK=$(xcrun --sdk iphoneos --show-sdk-path)
swift build --target HighlightKit \
  --triple arm64-apple-ios18.0 --sdk "$SDK"
```

The final 2026-07-10 gate compiled the entire target successfully against iOS
18.0; this catches accidental use of APIs newer than the package manifest.

## Layers

- **Fidelity** (`FidelityTests`, 375 cases) — the core guarantee. Every
  bundled grammar is highlighted and compared **token-for-token** (ranges and
  scope stacks), with relevance checked to a 0.001 tolerance, against
  reference fixtures generated by running the actual pinned highlight.js
  source over an upstream-derived corpus plus reviewed adversarial additions
  (`Tests/HighlightKitTests/Fixtures/<lang>/*.tokens.json`). Any grammar or
  engine change that diverges from the pinned fixture corpus fails here. See
  `PORTING.md` before changing fixtures; expected JSON must never be edited by
  hand merely to accept a failure.
- **Engine units** — `RegexSourceTests`, `KeywordCompilerTests`,
  `TokenEmitterTests`, `ModeCompilerTests`, `CompilerValidationTests`,
  `PrefilterTests`, `SwiftPrefilterTests`, `NumberPrefilterTests`,
  `ArrowPrefilterTests`, and `MatcherResumeTests`: the compiler, matcher fast
  paths, keyword compilation, emitter merging, and resume/overlap paths are
  pinned directly and differentially where applicable.
- **Behavior** — `EngineBehaviorTests`, `EdgeCaseTests`, `AutoDetectTests`,
  `IncrementalTests`, and `LanguageRegistryTests`: public API,
  generation-consistent registration and lazy compilation, auto-detection,
  illegals, resumable parser state, UTF-16/emoji offsets, empty input, and
  sub-language fallbacks.
- **Themes** — `ThemeTests`, `DynamicThemeTests`: scope dot-path fallback,
  attributed-string rendering, bold/italic traits, adaptive light/dark.
- **Stress & memory** — `StressTests`: steady-state footprint over 500
  runs, hostile inputs (deep nesting, unterminated strings, binary),
  concurrent mixed-language highlighting.
- **Performance** — `PerformanceTests` (release only, `HIGHLIGHT_BENCH=1`):
  throughput floor + cold-start ceiling as regression guards. See
  [`PERFORMANCE.md`](PERFORMANCE.md).

## Coverage

Generate coverage from the exact revision under review:

```sh
swift test --enable-code-coverage
swift test --show-codecov-path
```

The second command prints the exported report path. Coverage percentages are
not checked into this document because they become stale immediately. Core
logic changes should cover every observable branch; genuinely defensive or
platform-conditional branches require an explicit review note and the closest
reachable regression test rather than artificial coverage-only behavior.

The final 2026-07-10 audit is recorded as a dated exception to that general
rule. On Swift 6.3.2, 211 tests / 26 suites (including all 375 fidelity
parameters) produced the following `Sources/HighlightKit/Core` result:

| Metric | Covered | Raw llvm-cov rate |
|---|---:|---:|
| Lines | 3,529 / 3,538 | 99.75% |
| Functions / instantiations | 394 / 395 | 99.75% |
| Regions | 1,503 / 1,521 | 98.82% |

All normally reachable Core lines and functions are covered. The nine raw
missed lines are intentionally retained safety contracts rather than behavior
hidden from tests: six reconstruct compiler-error categories that the current
nonthrowing factory/`ModeCompiler` error domain cannot produce, two are a
forward-cache exhaustion guard dominated by its public entry precondition, and
one is the lazy diagnostic autoclosure of the `HighlightToken` nonempty-scope
precondition (executed only in a crashing process). Direct tests pin the closest
boundaries. Swift's coverage mapping reports no branch counters; the remaining
uncovered regions are those same invariants plus nondeterministic task-
cancellation scheduling windows. We report the raw rate rather than deleting
defensive checks or adding production hooks merely to print 100.00%.

## Differential fuzzing against highlight.js

Beyond the corpus fixtures, `Scripts/difftest.py` tokenizes seeded random and
mutated inputs with both this engine and a highlight.js 11.11.1 checkout. The
2026-07-10 all-language campaign found **0 comparable divergences across
28,750 default-campaign inputs / 65 languages**. Generated mutations inject
only ASCII/NUL, while 160 corpus-derived inputs retain non-ASCII text. The
reference harness reported and source-bounded 106 synthetic EOF-newline units;
Swift emitted no out-of-range token. See `FIDELITY.md` for the reproducible
invocation, scope of that evidence, and the documented ICU-vs-JavaScript
Unicode difference.

## Concurrency (ThreadSanitizer)

Thread Sanitizer is a separate instrumented run, not part of plain
`swift test`:

```sh
swift test --sanitize=thread \
  --filter 'LanguageRegistryTests|IncrementalTests|StressTests|CoreCoverageCompletionTests'
```

Run it after changes to registry publication, lazy compilation,
continuations, callbacks, or other shared state. Record the OS, Swift
toolchain, selected suites, and sanitizer result in the change report; do not
infer race-freedom from an ordinary test run.

Final 2026-07-10 gate (macOS 26.5.1, Swift 6.3.2): Registry, Incremental,
Stress, and Core Coverage suites ran **63 tests / 4 suites in 29.557 s**, exited
0, and reported **0 ThreadSanitizer warnings**. This supersedes the rejected
`AtomicLazyReference` publication run documented in `PERFORMANCE.md`.

## Leak detection

Use the production configuration and an explicit workload:

```sh
swift build -c release
leaks --atExit -- .build/release/highlight-bench 20 javascript
```

The 2026-07-10 theme-cache A/B audit reported **0 leaks** for both release
binaries. That is a recorded result, not a permanent guarantee; rerun it after
lifecycle or cache-ownership changes. `ModeCompilerTests` deterministically
exercise graph release, while
`StressTests.repeatedHighlightingHasStableFootprint` checks for per-run growth.

## Profiling / benchmarking

`swift run -c release highlight-bench [runs] [language] [file|--incremental]`
is the standalone host for `sample`/`leaks`. `--incremental` measures the
block-editor line-by-line workload. Per-rule cost instrumentation is opt-in:

```sh
HIGHLIGHT_BENCH=1 swift test -c release \
  -Xswiftc -DDEBUG_MATCH_STATS --filter ruleCosts
```

See [`BENCHMARKS.md`](../BENCHMARKS.md) for user-facing workloads and
[`PERFORMANCE.md`](PERFORMANCE.md) for the adopt/reject log and paired A/B
protocol.
